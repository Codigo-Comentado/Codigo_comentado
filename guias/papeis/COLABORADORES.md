# COLABORADORES

**Estrutura, responsabilidades e princípios de atuação**

*Aprender Programação Ensinando Programação*

---

## 1. Introdução

Os colaboradores são a base do Código Comentado.

São eles que transformam conhecimento em conteúdo, ideias em exemplos práticos e experiências individuais em materiais que podem ajudar outras pessoas a aprender programação.

O projeto existe através da colaboração de pessoas com diferentes níveis de experiência, perspectivas e conhecimentos.

Por isso, qualquer pessoa que contribua de forma construtiva para o Código Comentado possui um papel importante na construção do projeto.

A colaboração pode acontecer de diferentes formas, incluindo:

- Desenvolvimento de exemplos de código;
- Criação de explicações;
- Revisão de conteúdos;
- Identificação de erros;
- Sugestão de melhorias;
- Criação de desafios;
- Atualização da documentação;
- Discussões técnicas;
- Apoio a outros colaboradores.

## 2. Objetivo da Função

O principal objetivo do Colaborador é contribuir para a construção, evolução e melhoria do conhecimento compartilhado dentro do Código Comentado.

O colaborador não precisa saber tudo. Também não precisa ser especialista na linguagem ou no tema que está contribuindo.

O mais importante é possuir disposição para:

> Aprender, compartilhar, construir e evoluir.

A contribuição deve buscar transformar conceitos de programação em conteúdos claros, acessíveis e compreensíveis.

> **PRINCÍPIO FUNDAMENTAL**
>
> Você não precisa dominar um assunto para contribuir.
> Aprender também faz parte da contribuição.

## 3. Principais Responsabilidades

### 3.1 Criar conteúdos

Contribuir com a criação de conteúdos relacionados à linguagem ou área do projeto.

Esses conteúdos podem incluir:

- Exemplos de código;
- Explicações;
- Exercícios;
- Desafios;
- Analogias;
- Demonstrações práticas;
- Comentários linha a linha;
- Materiais complementares.

O objetivo não é apenas escrever código.

O objetivo é ajudar outra pessoa a entender o código.

### 3.2 Explicar o código

No Código Comentado, o código deve ser acompanhado de explicação.

O colaborador deve buscar responder perguntas como:

- O que esse código faz?
- Por que ele foi escrito dessa forma?
- Qual problema ele resolve?
- Quais conceitos estão sendo utilizados?
- O que aconteceria se determinada parte fosse alterada?

A explicação deve buscar ensinar o raciocínio por trás do código.

### 3.3 Seguir os padrões do projeto

Os colaboradores devem conhecer e respeitar as diretrizes definidas pelo projeto.

Isso inclui:

- Estrutura dos arquivos;
- Organização dos diretórios;
- Padrões de nomenclatura;
- Formatação do código;
- Convenções de comentários;
- Organização das explicações;
- Regras de contribuição;
- Fluxo de Pull Requests.

Os padrões existem para manter o projeto consistente e facilitar a colaboração.

### 3.4 Participar das revisões

A revisão não é responsabilidade exclusiva dos Representantes de Linguagem ou dos Mantenedores.

Todo colaborador pode contribuir com revisões.

Uma revisão pode identificar:

- Erros técnicos;
- Problemas de lógica;
- Explicações confusas;
- Erros de ortografia;
- Melhorias no código;
- Possíveis simplificações;
- Conteúdos que precisam de mais contexto.

Revisar não significa procurar erros para criticar alguém.

Revisar é ajudar o conteúdo a ficar melhor.

### 3.5 Participar das discussões

Os colaboradores são incentivados a participar das discussões técnicas e organizacionais do projeto.

Isso pode acontecer através de:

- Issues;
- Pull Requests;
- Discussões;
- Reuniões;
- Canais da comunidade.

Uma dúvida pode revelar uma falha na explicação.

Uma sugestão pode melhorar todo o projeto.

Uma opinião diferente pode apresentar uma solução melhor.

### 3.6 Identificar oportunidades de melhoria

Os colaboradores devem observar o projeto e sugerir melhorias.

Isso pode incluir:

- Conteúdos ausentes;
- Explicações que podem ser aprimoradas;
- Erros;
- Problemas na organização;
- Melhorias na documentação;
- Novas ferramentas;
- Novas abordagens de ensino.

Não é necessário esperar alguém solicitar uma melhoria.

Se algo pode ser melhorado, a sugestão é bem-vinda.

### 3.7 Compartilhar conhecimento

O Código Comentado possui como base o compartilhamento de conhecimento.

Por isso, colaboradores são incentivados a:

- Explicar conceitos;
- Ajudar pessoas com dúvidas;
- Compartilhar descobertas;
- Apresentar diferentes formas de resolver problemas;
- Compartilhar materiais úteis;
- Incentivar outros colaboradores.

## 4. Formas de Colaboração

Existem diferentes formas de colaborar com o projeto.

### 4.1 Contribuição de código

Criar exemplos de código relacionados aos temas estudados.

### 4.2 Contribuição de explicação

Criar ou melhorar comentários e explicações.

### 4.3 Contribuição de revisão

Analisar o trabalho de outros colaboradores e sugerir melhorias.

### 4.4 Contribuição de documentação

Melhorar:

- README;
- Guias;
- Documentação;
- Tutoriais;
- Instruções.

### 4.5 Contribuição através de Issues

Criar Issues para:

- Sugerir novos conteúdos;
- Relatar problemas;
- Identificar erros;
- Propor melhorias.

### 4.6 Contribuição através da comunidade

Ajudar outras pessoas através de:

- Discussões;
- Reuniões;
- Discord;
- Conversas técnicas;
- Compartilhamento de conhecimento.

Toda contribuição que ajuda o projeto a evoluir é uma forma válida de colaboração.

## 5. Atuação no Fluxo de Desenvolvimento

O colaborador participa do ciclo de construção do conhecimento.

**Fluxo básico:**

1. Identificação de um tema ou problema
2. Criação ou escolha da Issue
3. Desenvolvimento do conteúdo
4. Criação do Pull Request
5. Revisão colaborativa
6. Ajustes necessários
7. Validação
8. Integração ao projeto

Esse processo pode variar conforme o tipo de contribuição.

O mais importante é garantir que o conteúdo seja construído de forma organizada e colaborativa.

## 6. Pull Requests

Ao criar um Pull Request, o colaborador deve buscar fornecer informações suficientes para que outras pessoas compreendam a contribuição.

O Pull Request deve explicar:

- O que foi feito;
- Qual problema foi resolvido;
- Qual conteúdo foi adicionado;
- Quais conceitos foram abordados;
- Se existe alguma Issue relacionada.

O colaborador também deve estar aberto a receber sugestões e realizar ajustes.

Um Pull Request não é uma versão definitiva.

Ele é uma proposta de contribuição que pode evoluir através da colaboração.

## 7. Como realizar uma boa revisão

Uma boa revisão deve ser:

**Clara**
A pessoa deve compreender o que precisa ser ajustado.

**Respeitosa**
O objetivo é melhorar o conteúdo, não diminuir quem contribuiu.

**Construtiva**
Sempre que possível, a sugestão deve apresentar uma alternativa ou explicar o problema identificado.

**Técnica**
As observações devem estar relacionadas ao conteúdo e às regras do projeto.

**Exemplo de uma boa revisão**

❌ "Esse código está errado."

✅ "Talvez seja interessante utilizar essa abordagem porque ela evita determinada situação. Uma alternativa seria..."

A forma como uma sugestão é apresentada influencia diretamente a qualidade da colaboração.

## 8. O que o Colaborador não deve fazer

Para preservar o ambiente colaborativo, o Colaborador não deve:

- Desrespeitar outros participantes;
- Utilizar críticas pessoais em revisões;
- Copiar conteúdo sem respeitar direitos autorais;
- Apresentar código de terceiros como se fosse próprio;
- Ignorar deliberadamente as regras do projeto;
- Bloquear contribuições por motivos pessoais;
- Criar conflitos desnecessários;
- Desencorajar pessoas que estão começando;
- Tratar dúvidas como motivo de vergonha;
- Considerar sua forma de resolver um problema como a única possível.

## 9. Níveis de Conhecimento

O Código Comentado é construído para pessoas em diferentes momentos da jornada de programação.

Por isso, colaboradores podem estar:

- Começando a estudar programação;
- Aprendendo a sua primeira linguagem;
- Consolidando fundamentos;
- Estudando conceitos avançados;
- Desenvolvendo experiência profissional.

Todos podem contribuir.

Uma pessoa iniciante pode contribuir com:

- Uma dúvida importante;
- Uma explicação simples;
- A identificação de um ponto confuso;
- Uma perspectiva diferente.

Uma pessoa experiente pode contribuir com:

- Boas práticas;
- Revisões técnicas;
- Arquitetura;
- Mentoria;
- Discussões mais avançadas.

Uma dúvida de iniciante pode melhorar a explicação para milhares de pessoas.

## 10. Relação com os Representantes de Linguagem

Os colaboradores trabalham diretamente com os Representantes de Linguagem.

O Representante atua como uma referência e pode ajudar com:

- Dúvidas técnicas;
- Organização dos conteúdos;
- Direcionamento de contribuições;
- Padrões da linguagem;
- Evolução da trilha de aprendizado.

Entretanto, o Representante não substitui a autonomia do Colaborador.

A relação deve ser baseada em:

- Apoio.
- Troca.
- Colaboração.
- Aprendizado.

## 11. Relação com os Mantenedores

Os colaboradores também podem interagir diretamente com os Mantenedores.

Essa interação pode acontecer para:

- Sugerir melhorias estruturais;
- Relatar problemas;
- Propor mudanças;
- Solicitar apoio;
- Contribuir para decisões importantes.

Os Mantenedores existem para cuidar da estrutura do projeto.

Os colaboradores existem para construir e evoluir o conhecimento.

Ambas as funções são importantes para o funcionamento do Código Comentado.

## 12. Perfil Esperado

Espera-se que o Colaborador demonstre:

- Curiosidade;
- Disposição para aprender;
- Interesse em compartilhar conhecimento;
- Respeito pelos demais participantes;
- Abertura para receber feedback;
- Compromisso com a qualidade;
- Responsabilidade com suas contribuições;
- Disposição para colaborar;
- Humildade para reconhecer que sempre existe algo novo para aprender.

## 13. Definição Oficial da Função

O colaborador é responsável por contribuir para a construção, evolução e disseminação do conhecimento dentro do Código Comentado. Sua atuação pode acontecer através da criação de conteúdos, desenvolvimento de exemplos, revisão, documentação, discussões, sugestões e apoio a outros participantes.

A colaboração é baseada no aprendizado contínuo, no compartilhamento de conhecimento e na construção coletiva. Não é necessário possuir domínio absoluto sobre um tema para contribuir, pois aprender também faz parte do processo de colaboração.

## 14. Considerações Finais

Ser colaborador significa fazer parte da construção de algo maior do que o conhecimento individual.

Cada linha de código pode ensinar.

Cada comentário pode esclarecer.

Cada revisão pode melhorar.

Cada dúvida pode revelar uma oportunidade de aprendizado.

Cada contribuição pode ajudar alguém que ainda nem chegou ao projeto.

No Código Comentado, colaborar não significa apenas adicionar código a um repositório.

Colaborar significa ajudar a transformar conhecimento em compreensão.
